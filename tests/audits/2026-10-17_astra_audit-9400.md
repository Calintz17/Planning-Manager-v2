## Incidents de code

### P1 — Une valeur saisie explicitement devient un héritage silencieux

`saveAgentEditor`, lignes 7797–7813 :

```js
var weeklyHours = regulations.weekly_hours > 0 &&
  Math.abs(hoursIn - regulations.weekly_hours) < 1e-6 ? null : hoursIn;
```

Reproduction navigateur : saisir/enregistrer 37,5 avec défaut 37,5 → `weekly_hours:null`. Changer le défaut boutique à 40 → `contractHours(a)` passe à 40 sans modifier le contrat de l'agent. C'est incompatible avec une valeur contractuelle propre à la personne.

Correction ciblée : conserver `weekly_hours: hoursIn` dès saisie explicite. Réserver null aux valeurs réellement non renseignées, avec une action explicite « utiliser le défaut » si nécessaire. Le défaut peut préremplir une nouvelle fiche ; il ne doit pas réécrire implicitement une décision déjà enregistrée. Prévoir également une date d'effet : modifier aujourd'hui un contrat ne doit pas revaloriser tout l'historique.

### P1 — Les crédits d'absence ne respectent pas le calendrier individuel

`monthHoursUsed`, lignes 3412–3424 : `dayV = contractHours(a)*60/5`, puis plafond `5*w.days/7-w.units`.

Mesures indépendantes sur cellules synthétiques :

| Cas | Compteur actuel |
|---|---:|
| Une absence dimanche 1er novembre, contrat 37,5 h | 5,357 h |
| Une absence lundi 2 novembre, même contrat | 7,5 h |
| PT fixe 21 h, lundi–mercredi 10h–18h avec 1h non payée : absence lundi | 4,2 h au lieu des 7 h de sa journée fixée |
| Même PT : absence jeudi, hors jours fixes | 4,2 h |
| Même PT : jeudi OFF, férié fermé | 4,2 h |

Le plafond proportionnel fait artificiellement coïncider un mois entier d'absence avec la référence. Cette égalité ne valide pas les journées individuelles. Le calcul dépend de la frontière du mois au lieu des heures prévues sur la journée. L'absence ne doit pas créer un crédit sur un repos connu ; la bonne référence d'un PT fixe est déjà disponible.

Correction : un crédit déterminé **par date**, sans écrêtage selon la portion de semaine affichée. Ordre de référence : horaire individuel fixe applicable → planning de référence avant absence → valeur métier explicitement configurée si l'horaire est inconnu. Un repos connu vaut zéro crédit. Un inconnu reste à résoudre ; ne pas inventer cinq jours pour tous les contrats. Crédit et compteurs doivent rester identiques si l'on consulte la semaine entière ou chacun de ses deux mois séparément.

### P1 — `finalCheck` certifie une cellule absente ou un code de shift inconnu

Lignes 7485–7493 :

function resAt(a, ds) {
  return inMonth[ds] ? ((cells[ds] || {})[a.id] || null) : ctx.outside(a, ds);

// known(...) considère tous les jours inMonth comme connus.

Sonde moteur : mois nominal, journées extérieures explicitement connues OFF. Résultat original `checked`. Supprimer une cellule vendeur travaillée (`a09`, 1er novembre) : toujours `checked`, aucune inconnue. Remplacer par `{code:'NONEXISTENT'}` : toujours `checked`. La couverture reste suffisante grâce aux autres personnes ; le validateur ne voit donc pas la donnée invalide.

Correction : un contrôle de structure avant les règles. Pour chaque agent actif/date requise, exiger une cellule explicite ; `OFF` connu est différent d'une cellule absente. Vérifier le code dans le catalogue ou la liste des codes spéciaux, le type de demi-journée et le corner. Une absence de cellule alimente `unknown`; un code invalide doit produire une erreur de données bloquante, pas zéro heure.

## Arbitrages à séparer des bugs

1. **Période et plafond.** Le résultat historique préféré ne peut pas annuler « jamais au-dessus ». Recommandation : conserver la saisie H/semaine et la référence choisie `H*52/12` tant qu'une autre règle n'est pas explicitement validée. Si le plafond mensuel reste impératif, le moteur doit l'appliquer aux heures imputées au contrat ; un plan impossible reste un résultat à traiter, pas un plafond assoupli silencieusement. La mensualisation de paie n'est cependant pas automatiquement une autorisation d'aménager la durée du travail au mois. Vérifier le régime réellement appliqué par l'entreprise.
2. **Pauses BM.** 37,5 h de contrat et les amplitudes de shifts sont compatibles avec deux pauses payées, mais ne le prouvent pas. Confirmer contrat/accord/usage. Ne pas changer le déjeuner pour forcer les chiffres à coïncider.
3. **Absence flexible sans planning de référence.** La durée d'une journée ne se déduit pas des seules heures hebdomadaires. Pour 21 h, trois jours de 7 h et cinq jours de 4,2 h donnent le même contrat mais des crédits différents. Proposition : utiliser le planning de référence, et conserver une saisie exceptionnelle du crédit si aucune référence fiable n'existe.

## Critique d'architecture : progresser sans refaire tout CAST

La 9.3.65 apporte de vrais progrès : copie des entrées, restaurations via try/finally, contrôle final extrait, mouvements bornés à 300 essais et conservation des changements manuels. Les priorités ne sont plus uniquement une suite de réparations aveugles.

Trois simplifications nécessaires avant de multiplier les paramètres :

### 1. Séparer trois grandeurs, sans trois formulaires

- minutes de présence disponible sur le floor : trafic/couverture ;
- minutes de travail effectif : contraintes de durée/repos ;
- minutes imputées au contrat : travail, formation, crédits d'absence.

Une pause payée n'est pas nécessairement du travail effectif. `paidMinOf` est actuellement réutilisé pour ces notions ; `monthHoursUsed` mélange présence et crédits. Le manager peut garder une seule saisie d'heures contractuelles, mais le moteur a besoin de résultats distincts.

Interface interne proposée :

```js
accountDay(agent, date, cell, context)
// => { floorIntervals, effectiveMinutes, contractMinutes,
//      absenceCreditMinutes, source, known }
```

Aucune logique séparée de comptage dans l'export, la fiche, le validateur ou le Monthly : tous consomment ce résultat.

### 2. Rendre le contrôle réellement indépendant

`finalCheck(cells, ctx)` lit encore `agents`, `regulations`, catalogue et calendrier globaux. Son ctx ne contient que dates et fonction outside. `computeMonthlyPlan` réaffecte temporairement les globals avec `useMonthlyInputs`. C'est une transition acceptable, pas un validateur portable de snapshot/export.

Passer explicitement le contexte aux fonctions de comptage et au validateur d'abord. Ajouter la validation de forme et l'état incomplet. Le même contexte daté doit être partagé par génération, vérification et affichage. Supprimer ensuite la permutation des globals ; ne pas conserver deux chemins parallèles durablement.

### 3. Une frontière de persistance atomique

La fiche fait `retail_agents.update` puis `retail_agent_prefs.upsert` séparément (7819–7827). Une défaillance intermédiaire peut appliquer les nouvelles heures sans le nouvel horaire fixe. Les modifications manuelles multi-cases ont le même risque. Proposer une transaction serveur pour chaque opération métier liée, avec validation et journal dans cette transaction.

`paint` (7183–7186) sauvegarde de nouveau `newSnap` sans vérifier `check.status`. Un résultat `incomplete` ou `violation` peut donc devenir le snapshot enregistré. Si l'on souhaite conserver un brouillon, stocker son état ; ne pas confondre sauvegardé et validé. L'absence d'alerte visuelle demandée par Roman n'impose pas de perdre ce statut en base.

### Optimisation utile

- Garder l'ancien `work_pct` seulement dans une fonction de migration/compatibilité ; arrêter les conversions implicites dispersées.
- Retirer les labels/commentaires « 35h standard » de TRAINING_DAY : 450 minutes est une décision métier, pas 35/5.
- Mettre des assertions dans `regression-9400.cjs` : `assert` est importé mais jamais appelé. Le script affiche les différences, mais peut terminer avec succès après une régression. Tester les nouveaux contrats hétérogènes, pas seulement l'identité des anciennes fixtures.
- Ne pas lancer de grand nettoyage CSS en même temps que cette migration : aucun défaut de thème bloquant trouvé, supprimer seulement ce dont l'inutilité est vérifiée.

## Vérification juridique ciblée — France, pas homologation des neuf pays

Sources officielles consultées le 17-10-2026 :
- https://www.service-public.gouv.fr/particuliers/vosdroits/F18205 : pause minimale et rémunération ; une pause peut être rémunérée sans être du travail effectif.
- https://www.service-public.gouv.fr/particuliers/vosdroits/F125 : heures perdues pour maladie/congé/jour férié non récupérables dans le dispositif de récupération.
- https://www.legifrance.gouv.fr/codes/article_lc/LEGIARTI000033020898/2026-09-11 : L3133-2, jours fériés chômés.
- https://www.service-public.gouv.fr/particuliers/vosdroits/F2391 : le traitement des congés payés dans les heures supplémentaires ne se généralise pas à toute absence ou à tout plafond de travail effectif.
- https://www.service-public.gouv.fr/particuliers/vosdroits/F33359 : maintien de salaire et horaire réel illustré ; ne fournit pas une règle universelle H/5.

Conclusion : non-récupération ne signifie pas que tout jour calendaire d'absence vaut H/5. OFF de repos connu ne crée pas une dette. Il ne vaut pas non plus systématiquement un crédit d'absence. Les codes doivent conserver cette distinction.

Ne pas pousser la note pays telle quelle en pré-réglages : elle mélange heures usuelles, seuils d'heures supplémentaires et plafonds, et Ontario n'est pas tout le Canada ; les États-Unis nécessitent l'État. Les offres d'emploi ne prouvent ni le contrat CELINE ni une règle nationale. Aucune écriture de presets effectuée dans cet audit.
