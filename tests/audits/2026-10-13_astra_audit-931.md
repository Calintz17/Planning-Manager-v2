## SQL optionnel : corrections restantes
### P1 — rattachement agent/boutique mal qualifié
with check (exists (
 select 1 from retail_agents a
 where a.id = agent_id and a.store_id = store_id
));

Le store_id non qualifié de droite peut se résoudre sur la table intérieure retail_agents : le test devient a.store_id=a.store_id, pas la boutique de la nouvelle ligne. Un agent existant associé à une autre boutique n'est alors pas rejeté par ce test.
Correction :
a.id = retail_planning_edits.agent_id
and a.store_id = retail_planning_edits.store_id

Analogue local exécuté sous SQLite avec agent-A/store-A et une ligne journal agent-A/store-B : condition non qualifiée vraie, condition qualifiée fausse. La migration PostgreSQL et les rôles Supabase n'ont pas été exécutés ; compléter par un vrai test PostgreSQL de refus cross-store.
Documentation primaire de portée des noms :
https://www.postgresql.org/docs/current/queries-table-expressions.html

### P1 si mise à niveau depuis 9.3.0 — anciennes politiques conservées
Le SQL 9.3.1 ajoute « edits insert only », mais ne supprime ni « edits read » ni « edits insert » créées par 9.3.0. Une politique supplémentaire ne retire pas les permissions des anciennes politiques permissives.
CREATE TABLE IF NOT EXISTS ne met pas à niveau les CHECK/FK de la table 9.3.0 existante.
Correction : migration de mise à niveau explicite, DROP POLICY IF EXISTS des deux anciennes politiques, ajout/validation contrôlée des contraintes, puis politique qualifiée. Tester installation neuve et upgrade 9.3.0.
Documentation primaire :
https://www.postgresql.org/docs/current/sql-createpolicy.html
Rôles/grants effectifs non testés sur une table déployée.
